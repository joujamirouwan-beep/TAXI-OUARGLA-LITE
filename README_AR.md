# طاكسي ورقلة لايت — Core Integration Pack V3.10.1

حزمة تأسيس مصدرية قابلة للدمج اليدوي، وليست مشروع Flutter كاملاً ولا ملف APK/AAB.

## ما تتضمنه

- نموذج حالات الرحلة الصارم، دون `en_route`.
- `RideModel` مطابق لأعمدة جدول `rides` في SQL V2 المرجعي.
- `RideService` بعقود RPC V2 الفعلية في ملف SQL المرجعي: أسماء المعاملات `p_*` والنتائج Boolean.
- إنشاء الرحلة عبر INSERT محدود الأعمدة كما يسمح SQL V2، وليس عبر RPC غير موجود في ذلك المخطط.
- `UserProfile` و`ProfileService` مع عدم ابتلاع أخطاء parsing.
- `RideDataSource` و`RideRepository` لعزل قراءة Realtime عن منطق الخدمة.
- اختبارات وحدات أولية للحالات والملف الشخصي وقرار التوجيه.
- `AuthWrapper` لمتابعة تسجيل الدخول والخروج وتبدل الجلسة.
- `ProfileRouter` لتوجيه الراكب والسائق المعتمد والسائق قيد الاعتماد والإدارة.
- `AppDependencies` كنقطة تركيب واحدة للخدمات والمستودع.

## دمج الحزمة

1. احتفظ بمعرف Android كما هو: `com.taxiouargla.lite`.
2. انسخ مجلد `lib/` إلى المشروع بعد مقارنة الملفات المتداخلة وعدم استبدال شاشات التطبيق عشوائياً.
3. ادمج الاعتماديات من `pubspec.dependencies.yaml` داخل `pubspec.yaml` الحالي، ولا تستبدل بيانات التطبيق أو assets.
4. راجع `docs/AUTH_ROUTING_AR.md` لتركيب المصادقة والتوجيه مع أسماء الشاشات الفعلية في مشروعك.
5. شغّل محلياً: `flutter pub get` ثم `dart format lib test` ثم `flutter analyze` ثم `flutter test`.
6. لا تعتمد أي SQL migration قبل مطابقة العقد مع قاعدة Supabase الفعلية وفحص التكرارات وسياسات RLS.

## ملاحظات صريحة

- لا تتضمن الحزمة `main.dart` أو شاشات التطبيق أو إعدادات Android/Gradle؛ لا تعتبرها مشروعاً مستقلاً قابلاً للبناء بعد.
- لم يتم تشغيل Flutter أو Dart في بيئة إعداد هذه الحزمة؛ الاختبارات مضافة ولم تُنفذ هنا.
- `AuthWrapper` و`ProfileRouter` وحدات توجيه قابلة للربط وليستا شاشات تسجيل دخول أو لوحات مكتملة.
- `ProfileService` يفترض وجود أعمدة `id`, `role`, `is_verified`, `is_online` في `profiles` كما في SQL V2 المرجعي. يجب التحقق من قاعدة المستخدم الفعلية.
- `RideModel` يتبع SQL V2، لذلك لا يحتوي `review_comment` لأنه غير موجود في ذلك المخطط.
- `RideService.createRide` يستخدم INSERT المباشر المقيّد بسياسة RLS وGRANT في SQL V2. هذا لا يمنح العميل صلاحية UPDATE/DELETE على الرحلات.
- صلاحية `admin` في الواجهة ليست حماية أمنية؛ فرض الصلاحيات يجب أن يكون في قاعدة البيانات.

## حالة الإصدار

**NO-GO — PRODUCTION** حتى يتم فحص قاعدة البيانات الفعلية، ودمج الحزمة في المشروع الأصلي، ونجاح `flutter analyze` و`flutter test` والبناء والاختبار على جهاز.
